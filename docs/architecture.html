System Architecture

Factory Inventory Management System

A full-stack demo application for inventory tracking, order management, demand forecasting, and spend analytics. A Vue 3 single-page app talks over HTTP to a Python FastAPI service that serves read-only mock data loaded from JSON files — no database, no authentication.

Vue 3 + Vite SPA FastAPI (Python) In-memory JSON data REST over JSON / axios Two processes · ports 3000 & 8001

1. System architecture

Two independently run processes during development; the SPA is a static build in production.

Presentation

Vue 3 SPA (client/)

Composition API, one Vite dev server on port 3000. Six route-level views render tables and custom SVG charts. Raw API responses are held in refs; everything shown is a computed derived from them. Cross-view state (the 4 global filters, mock auth, locale) lives in singleton composables.

Transport

REST over JSON

client/src/api.js wraps axios with one method per endpoint, serializing the active filters into query-string params. Base URL is hard-coded to http://localhost:8001/api. The backend enables permissive CORS (allow_origins=["*"]) so the two ports talk directly.

Application

FastAPI service (server/main.py)

Stateless route handlers. Shared helpers apply_filters() (warehouse / category / status) and filter_by_month() (month or Q#-2025 quarter) run in plain Python over the in-memory lists. Reports endpoints aggregate orders into quarterly and monthly rollups on the fly. Pydantic models validate and shape responses; /docs serves live OpenAPI.

Data

JSON fixtures (server/data/)

mock_data.py reads seven JSON files once at import time into module-level lists. There is no database and no write path — mutations are not persisted, and a restart resets all state. generate_data.py can regenerate the fixtures.

3. Data flow — a filtered request

What happens when a user changes a filter on the dashboard.

  1. User changes a filter in FilterBar.vue (Time Period, Warehouse, Category, or Order Status). The bound ref in the useFilters singleton updates.
  2. A view watcher fires. The active view calls getCurrentFilters(), which maps the four refs into an API params object (period → month).
  3. api.js builds the request. The matching method drops any value equal to 'all', serializes the rest with URLSearchParams, and issues GET http://localhost:8001/api/<resource>?….
  4. FastAPI handles the route. The handler receives the query params as optional arguments and passes the in-memory list through apply_filters() then filter_by_month() (direct YYYY-MM match or Q#-2025 quarter expansion).
  5. Summary / report endpoints aggregate the filtered rows — inventory value, low-stock count, pending orders, quarterly revenue, monthly trends.
  6. Pydantic serializes the result against the response_model and FastAPI returns JSON.
  7. The view stores the response in a raw ref (allOrders, inventoryItems, …).
  8. Computed properties recompute — derived tables, totals, and SVG chart series — and Vue re-renders. No client-side caching; each filter change is a fresh round trip.

6. Key patterns & constraints

  • Raw refs, derived computeds. API responses go into refs untouched; tables, totals, and chart series are all computed. Never mutate a computed.
  • Four filters, one shape. Time Period, Warehouse, Category, Order Status apply everywhere via query params. Inventory has no time dimension, so it ignores month.
  • Stateless backend. Every request re-filters the full in-memory list; no caching, no pagination, no indexes. Fine for the fixture sizes (≤ 250 rows).
  • No persistence. Data is read from JSON at startup and never written back. Restart = clean slate.
  • Not production-ready. No auth, permissive CORS, no rate limiting, no input validation beyond Pydantic types. Local demo only.
  • Charts are hand-built SVG. No charting library; CSS Grid for layout, slate/gray palette, no emojis in UI.
  • Run it: ./scripts/start.sh, or cd server && uv run python main.py and cd client && npm run dev. Frontend :3000, backend :8001, API docs at /docs.
